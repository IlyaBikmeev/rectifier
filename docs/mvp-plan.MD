# Rectifier MVP Plan

## Цель MVP

Собрать локальное устройство на Raspberry Pi, которое:

- показывает текущие температуры датчиков;
- показывает live-видеопоток с камеры;
- позволяет начать и остановить запись перегона;
- сохраняет историю перегонов локально;
- позволяет просматривать графики завершённых перегонов;
- работает автономно в локальной сети без зависимости от облака.

Grafana/Alloy остаются как дополнительная observability-система, но не являются обязательной частью Definition of Done MVP.

---

## 1. Фоновый опрос датчиков

Сейчас датчики читаются непосредственно из HTTP-обработчиков и при сборе `/metrics`.

Нужно перейти к схеме:

```text
DS18B20
   ↓
фоновый polling
   ↓
текущее состояние приложения
   ├── UI
   ├── /metrics
   └── SQLite
```

### Задачи

- [x] Добавить фоновый polling датчиков.
- [x] Интервал по умолчанию: 5 секунд.
- [x] Хранить текущее состояние датчиков в памяти.
- [ ] Хранить:
  - [x] ID;
  - [x] имя;
  - [x] температуру;
  - [x] время последнего успешного чтения;
  - [ ] статус online/offline/error (сейчас реализованы OK/ERROR; offline появится с пересканированием датчиков).
- [x] Сделать доступ к состоянию потокобезопасным.
- [x] UI и `/metrics` должны читать готовый snapshot, а не обращаться к железу напрямую.
- [x] Добавить `GET /api/status` для обновления UI без перезагрузки страницы.

### Definition of Done

- [x] Закрытие браузера не останавливает polling.
- [x] Несколько открытых вкладок не увеличивают число физических чтений датчиков.
- [x] Ошибка одного датчика не роняет приложение.

## 2. SQLite

SQLite должна стать локальным source of truth для истории.

### Текущее состояние

- [x] Подключить SQLite-драйвер.
- [x] Открывать базу при запуске приложения и проверять соединение.
- [x] Добавить встроенные в бинарник SQL-миграции через `embed.FS`.
- [x] Выполнять новые миграции последовательно и транзакционно.
- [x] Хранить текущую версию схемы в `PRAGMA user_version`.
- [x] Создать начальную схему данных.
- [x] Включить WAL mode, `foreign_keys` и `busy_timeout` через DSN.
- [x] Добавить индекс для чтения истории измерений.
- [ ] Добавить репозитории и операции чтения/записи.
- [ ] Сохранять обнаруженные датчики.
- [ ] Сохранять Batch, Run и измерения.
- [ ] Добавить буферизованную запись измерений.
- [ ] Сбрасывать буфер при Stop и graceful shutdown.
- [ ] В будущем хранить и проверять checksum применённых миграций.

### Сущности

```text
Batch
  └── Run
      ├── Sensors
      └── Measurements
```

### Таблицы

#### batches

- id
- name
- created_at
- updated_at
- comment

#### runs

- id
- batch_id
- type
- started_at
- stopped_at
- status

Типы run:

- `stripping`
- `rectification`

#### sensors

- id
- hardware_id
- name
- measurement_type
- unit
- enabled
- created_at
- updated_at

#### run_sensors

Снимок датчиков конкретного перегона.

Нужен, чтобы переименование датчика в будущем не меняло подписи старых графиков.

- run_id
- sensor_id
- sensor_name

#### measurements

- id
- run_id
- sensor_id
- measured_at
- value

Тип измерения и единица хранятся у датчика. Например:

```text
measurement_type = temperature
unit = celsius
```

### Настройки SQLite

- [x] WAL mode.
- [x] `foreign_keys = ON`.
- [x] `busy_timeout = 5000` миллисекунд.
- [x] Ограничить пул одним соединением.
- [x] Индекс под историю перегонов.

Пример:

```sql
CREATE INDEX idx_measurements_run_sensor_time
ON measurements(run_id, sensor_id, measured_at);
```

### Batch insert

Измерения не обязательно коммитить каждые 5 секунд.

Схема:

```text
polling
  ↓
channel / buffer
  ↓
writer goroutine
  ↓
flush каждые ~30 секунд
  ↓
одна SQLite transaction
```

Дополнительно flush:

- при Stop run;
- при достижении лимита batch;
- при shutdown приложения.

### Definition of Done

- После перезапуска приложения история остаётся.
- Измерения разных runs не перемешиваются.
- При штатном shutdown буфер полностью сбрасывается в SQLite.

## 3. Несколько DS18B20 и управление датчиками

На одной 1-Wire шине планируется до 6 температурных датчиков.

### Задачи

- Периодически пересканировать `/sys/bus/w1/devices/28-*`.
- Автоматически обнаруживать новые датчики.
- Сохранять новый hardware ID в SQLite.
- При отключении датчика не удалять его из БД.
- При повторном подключении узнавать его по hardware ID.
- Добавить возможность переименовать датчик через UI.
- Добавить enabled/disabled.
- Показывать online/offline/error.

### Метрики

Метрика:

```text
rectifier_temperature_celsius{
  sensor_id="28-...",
  sensor_name="Куб"
}
```

При переименовании должна использоваться новая label value.

### Definition of Done

- Подключённый новый DS18B20 появляется в UI.
- Пользователь может взять датчик в руку, определить его по изменению температуры и назвать.
- Имя переживает перезапуск.
- Отключение одного датчика не ломает остальные.

## 4. Batch и Run

Приложение должно понимать разницу между партией браги и отдельным перегоном.

Пример:

```text
Batch #1
├── Stripping #1
├── Stripping #2
└── Rectification
```

### Start

При старте:

- пользователь выбирает или создаёт Batch;
- выбирает тип Run;
- выбирает датчики, которые участвуют в этом Run;
- создаётся запись `runs`;
- начинается сохранение measurements.

### Stop

При остановке:

- завершается текущий Run;
- записывается `stopped_at`;
- статус становится `completed`;
- текущий measurement buffer сбрасывается в SQLite.

### Важно

Кнопки Start/Stop управляют только записью процесса.

Они не управляют:

- ТЭНом;
- клапанами;
- отбором;
- физическим аппаратом.

### Состояния

```text
STOPPED
   │
   │ Start
   ▼
RUNNING
   │
   │ Stop
   ▼
STOPPED
```

Одновременно может быть только один активный Run.

### Definition of Done

Можно записать:

- первый перегон №1;
- первый перегон №2;
- ректификацию;

в рамках одной Batch.

## 5. Главная страница

Главная страница — оперативный экран текущего состояния.

### Показывать

- состояние `RUNNING / STOPPED`;
- длительность текущего Run;
- кнопку `Начать перегон` или `Остановить перегон`;
- карточки датчиков;
- текущие температуры;
- статус датчиков;
- live-камеру.

Навигация:

```text
☰
├── Главная
└── История перегонов
```

## 6. Камера

Камера работает отдельным сервисом.

Схема:

```text
USB webcam
   ↓
/dev/video0
   ↓
uStreamer
   ↓
MJPEG localhost:8081
   ↓
Go reverse proxy
   ↓
/camera/stream
   ↓
<img src="/camera/stream">
```

### Почему так

Go-приложение не должно самостоятельно заниматься:

- V4L2;
- кодированием JPEG;
- видеокодеками.

### UI

На главной:

```html
<img src="/camera/stream" />
```

Браузер будет видеть live MJPEG без обновления страницы.

### Definition of Done

- Камера видна с телефона/ноутбука в локальной сети.
- Отключение камеры не ломает температурный мониторинг.
- Видео не записывается на SD в MVP.

---

## 7. История перегонов

Страница истории группирует Runs по Batch.

Пример:

```text
Партия #1
├── Первый перегон #1
├── Первый перегон #2
└── Ректификация
```

### Страница Run

Показывать:

- тип Run;
- дату;
- время начала;
- время окончания;
- длительность;
- участвовавшие датчики;
- график температур.

### Ось времени

Графики масштабировать от момента старта:

```text
00:00
00:30
01:00
...
04:12
```

При необходимости tooltip может показывать абсолютное время.

### API

HTML и данные графика разделить:

```text
GET /runs/{id}
GET /api/runs/{id}/measurements
```

На MVP отдавать raw measurements без downsampling.

### Definition of Done

После перезапуска Raspberry можно открыть старый Run и увидеть полный график.

---

## 8. Grafana и Alloy

Grafana остаётся дополнительной инженерной системой.

Использовать для:

- Prometheus metrics;
- Go runtime metrics;
- Raspberry system metrics;
- технической диагностики;
- экспериментов с PromQL.

Не считать Grafana частью основного UX MVP.

Основной пользовательский интерфейс — локальный Rectifier UI.

---

## 9. Автозапуск

После включения Raspberry ничего не должно запускаться вручную через SSH.

Нужны systemd units для:

- Rectifier;
- camera streamer;
- Grafana Alloy.

Production-режим должен запускаться с реальными DS18B20, а не с fake sensors.

---

## 10. Автономность

Система должна работать без интернета.

Без интернета должны продолжать работать:

- температурные датчики;
- SQLite;
- история;
- Start/Stop;
- локальный UI;
- MJPEG-камера.

Grafana Cloud при этом может быть недоступна.

---

## 11. Backup

SQLite должен иметь простой механизм резервного копирования.

Для MVP достаточно:

- корректного SQLite snapshot;
- возможности скопировать backup на Mac;
- инструкции восстановления.

Не копировать рабочий `.db` вслепую во время записи.

---

## 12. Корпус и подключения

Финальная V1 должна быть собрана в корпусе.

### Требования

- Raspberry Pi закреплена внутри;
- отдельная PCB/плата разводки датчиков;
- до 6 разъёмов DS18B20;
- один общий 1-Wire pull-up;
- датчики легко подключаются и отключаются;
- камера подключена аккуратно;
- доступно питание;
- предусмотрена вентиляция.

PCB и разъёмы перед эксплуатацией проверяются радиотехником.

---

## 13. Приёмочный тест

Перед первым реальным использованием провести длительный тест.

Проверить:

- работу 8–24 часа;
- несколько датчиков;
- отключение/подключение датчика;
- перезапуск приложения;
- перезагрузку Raspberry;
- отсутствие интернета;
- отключение камеры;
- запись SQLite;
- восстановление истории после reboot;
- корректный shutdown.

---

## Не входит в MVP

Пока не реализуем:

- управление ТЭНом;
- электромагнитные клапаны;
- автоматическое управление отбором;
- расходомер;
- весы;
- OLED;
- SaaS backend;
- аккаунты пользователей;
- MQTT;
- OTA;
- сложный rule engine;
- автоматические процессные alerts.

Это задачи следующих версий после эксплуатации MVP.

---

## Definition of Done MVP

MVP считается готовым, когда:

1. Устройство собрано и включается как законченная коробка.
2. Можно подключить до 6 DS18B20.
3. Новые датчики автоматически обнаруживаются.
4. Через UI датчику можно назначить имя.
5. На главной видны актуальные температуры.
6. На главной виден live MJPEG-поток камеры.
7. Можно создать Batch.
8. Можно начать Run.
9. Во время Run measurements записываются в SQLite.
10. Можно остановить Run.
11. Runs группируются по Batch.
12. В истории можно открыть завершённый Run.
13. Для Run строится график температур от `00:00` до окончания.
14. После reboot история сохраняется.
15. Система работает локально без интернета.
16. Rectifier, камера и Alloy автоматически запускаются через systemd.
17. SQLite можно корректно забэкапить и восстановить.
18. Grafana продолжает получать метрики, но не является обязательной для работы устройства.

После этого MVP используется на серии реальных перегонов без добавления крупных новых функций.
