# Технический долг

Этот файл хранит осознанно отложенные задачи. В него не переносятся проблемы,
из-за которых MVP может показывать ложное состояние записи, потерять основной
сценарий Start/Stop или нарушить целостность данных.

## Реализовано

- Start/Stop подключены к API, SQLite и `AppState`.
- Создание партии встроено в сценарий Start.
- Измерения активного Run сохраняются, график обновляется в UI.
- Активный Run восстанавливается после перезапуска сервиса.
- История группирует Runs по партиям и показывает сохранённые графики.

Перед MVP всё ещё нужен ручной сквозной тест: Start, несколько измерений,
перезапуск сервиса, восстановление Run и Stop.

## Отложено после MVP

- Сериализовать Start/Stop отдельным mutex и полноценно использовать состояния
  `STARTING` и `STOPPING`. До этого предполагаются один экземпляр сервиса и один
  пользователь; уникальный индекс защищает базу от второго активного Run.
- Ввести sentinel errors для storage и единый JSON-формат ошибок вместо
  строковых ответов и общего `500 Internal Server Error`.
- Дедуплицировать `sensor_hardware_ids` и отклонять второй JSON-объект или мусор
  после тела запроса. Штатный UI не создаёт такие запросы.
- Определить поведение, если новая партия создана, а следующий `POST /api/runs`
  завершился ошибкой. На MVP допустима неиспользованная партия.
- Добавить пакетную вставку измерений, retry/буферизацию и метрику ошибок записи.
  MVP может писать небольшой набор показаний простой транзакцией и логировать
  ошибку без гарантированной доставки.
- Корректно дожидаться завершения sensor polling при graceful shutdown.
- Явно отражать ошибки discovery/polling датчиков в логах и метриках.
- Заменить `PRAGMA user_version` отдельной таблицей истории миграций, когда
  миграции станут сложнее линейного локального набора.
- Добавить пагинацию или поиск партий, когда нативного select станет
  недостаточно для реального объёма данных.
- Добавить backend-тесты repository и HTTP-контрактов. На текущем этапе
  выполняются ручные сценарии, `go test ./...` и проверки SQLite.
- Поддержать внешние изменения SQLite или несколько экземпляров приложения.
  MVP предполагает один systemd-процесс, который единолично изменяет базу.

## Вне текущего этапа

- Runtime-rescan датчиков и состояние offline.
- Камера и live-видеопоток.
- OLED-интерфейс.
- Управление нагревом и другой автоматикой.
- Удалённое многопользовательское управление и авторизация.
